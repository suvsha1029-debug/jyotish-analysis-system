# Jyotish Varga JavaScript Engine

This is an isolated browser implementation. It does not import, edit, or replace
the existing Python/FastAPI application in the parent directory.

## Calculation profile

The interface now keeps three named calculation standards separate:

- **BPHS / Parāśari (primary):** Lahiri sidereal positions, mean nodes, whole-sign houses in D1 and every Varga. This profile alone supplies the main promise grade.
- **Classical KP (independent):** Krishnamurti ayanāṃśa, mean nodes and exact Placidus cusps. Natal and timing checks are displayed separately and never overwrite the Parāśari grade.
- **JHora screenshot-compatible (comparison):** equal houses centred on the Ascendant and an ayanāṃśa calibrated to the supplied 26 August 2003, 05:53:55 Amritsar reference. The exact reference reproduces 23°53′32.19″ and the supplied Mahadasha boundaries. Other dates are explicitly labelled calibrated comparisons because the JHora ayanāṃśa option name is not known.

The systems are never silently averaged. A disagreement remains visible for the reader to inspect.

- Swiss Ephemeris compiled to WebAssembly (`@swisseph/browser`)
- Built-in Moshier ephemeris, matching `pyswisseph` for the supported planets
- Lahiri sidereal mode
- Mean Rahu and Ketu
- D1, D2, D3, D4, D5, D9, D10, D11, D12, D16, D24, and D60 mappings matching `app.py`
- Whole-sign houses counted from each varga lagna
- Prediction workspace for money, career, authority, marriage, foreign residence, property, vehicles and gains
- Vimshottari MD-AD timeline with relationship geometry
- Seven-planet BAV and combined SAV Ashtakavarga matrix
- Functional lordship, sign dignity, Parashari aspects, dispositor chains and Arudha padas
- Configured wealth/status yoga evidence and Trivedi-style Rahu-Ketu controller routes
- Confidence shown as calculated evidence coverage, never as event probability
- North Indian, South Indian, and East Indian graphical chart layouts

D11 uses the P.V.R. Narasimha Rao Rudrāṃśa method. Because D11 is not
among the classical BPHS sixteen vargas and competing conventions exist, the
chosen method is documented explicitly rather than implied to be universal.

## Commands

On Windows, double-click `RUN_JAVASCRIPT_IN_CHROME.bat`. It builds the static
page, starts a local preview server, and opens the result in Google Chrome.
Keep the terminal window open while testing and press Ctrl+C when finished.

```powershell
npm install
npm test
npm run dev
npm run build
```

The production output is written to `dist/` and can be published as a static
site, including on GitHub Pages.

## Public API

```js
import { calculateChart } from "./src/varga-engine.js";
import { BrowserSwissEphemerisAdapter } from "./src/swisseph-adapter.js";

const ephemeris = await new BrowserSwissEphemerisAdapter().init();
const result = await calculateChart({
  date: "2003-08-26",
  time: "05:53:55",
  utcOffset: "+05:30",
  latitude: 31.6166667,
  longitude: 74.85,
}, ephemeris);
```

Tests include varga boundary cases, timezone and input validation, adapter state,
and a complete chart fixture generated by the existing Python Swiss Ephemeris
implementation.
